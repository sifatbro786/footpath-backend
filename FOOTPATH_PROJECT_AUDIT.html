1. Ek Nojore (Executive Summary)

Backend ta onek beshi mature tomar frontend er tulonay. API layer prai production-ready — server-side pricing, Mongo transactions, atomic stock decrement with oversell guard, SSLCommerz validation-API verification, cron-driven campaign engine — eshob already ache. Frontend e admin dashboard ~85% done, kintu customer-facing storefront kar্যত 0% — HomePage ekta placeholder, ar cart/PDP/checkout/order pages ekdom nei.

Tumi bolecho 60% — amar hisebe eta ~58%, tobe distribution ta unequal: backend 85%, admin UI 82%, storefront 6%.

Sob theke boro 3 ta blocker

  1. Payment flow broken end-to-end. Backend /order/success, /order/fail, /order/cancel e redirect kore — frontend e ei 3 ta route exist kore na. Manush taka diye 404 dekhbe.
  2. Guest order IDOR. GET /api/orders/:id — guest order hole kono auth chara full PII (name, phone, email, address) return kore. Order number sequential (ORD26082900001) → enumerate kora trivial.
  3. Guest cart nei. Backend cart protect-only, kintu order guest support kore. Storefront e localStorage cart + merge-on-login banate hobe.

3. Bug & Security Findings

3.1 Critical

CRITICAL  C-1 · Guest order IDOR — full PII leak

controllers/orderController.js:562

if (order.isGuest) {
    return res.status(200).json({ success: true, order });  // ← no auth at all
}

Order number generator sequential: ORD + YY + MM + DD + 0001. Keu ORD26082900001 theke loop chalale sob guest order er name, phone, email, full address, order items peye jabe. Fix: guest order e ekta accessToken (crypto random, order e store) generate koro, success URL e pathao, ar GET /:id e ?token= ba email/phone match require koro.

CRITICAL  C-2 · Payment redirect pages nei

Backend ${CLIENT_URL}/order/success?orderId=..., /order/fail, /order/cancel e redirect kore. AppRoute.jsx e ei route gulo nei → NotFoundPage. Payment successful hoyeo user 404 dekhbe. Highest priority frontend task.

CRITICAL  C-3 · getMyOrders guest e crash kore

orderRoutes.js:8 e optionalProtect use kora, kintu getMyOrders e req.user.id — guest hole TypeError → 500. Fix: route ta protect koro.

6. Architecture Suggestions

  • Backend layering — currently controller e business logic vari (orderController ~1100 line). pricingService / productCampaignService pattern ta already valo — ei pattern ta orderService, checkoutService, couponService e extend koro. Controller sudhu HTTP concern (parse → call service → shape response) handle korbe.
  • Repository layer — Mongoose query controller theke sriye repositories/ e nao. Test kora onek shohoj hobe, ar aggregation pipeline reuse kora jabe.
  • Validation — express-validator rule gulo route file e scattered. Ekta validators/ folder e centralize koro, per-resource file.
  • Frontend structure — features/ based colocation consider koro (features/cart/{api,components,hooks,store}) — admin+storefront duitai grow korle flat pages/components/api split ta unwieldy hobe.
  • Shared types — TypeScript e migrate na korleo, minimum ekta shared/constants.js rakho jekhane order status, payment status, location type enum ache — currently frontend e hardcoded string, backend enum er sathe drift korbe.
